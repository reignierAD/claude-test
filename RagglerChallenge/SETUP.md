## 3. Blockchain — Deploy Smart Contracts

### 3a. Install Hardhat dependencies

```bash
cd RagglerChallenge/Blockchain
npm install
```

### 3b. Create your `.env` file

```bash
cp .env.example signer-server/.env
```

Open `signer-server/.env` and fill in:

```env
# A wallet private key for deploying contracts.
# Fund it with tBNB from the faucet first.
DEPLOYER_PRIVATE_KEY=0xYOUR_DEPLOYER_PRIVATE_KEY

# A SEPARATE wallet private key used only to sign game results.
# This key never leaves your server.
GAME_SIGNER_PRIVATE_KEY=0xYOUR_SIGNER_PRIVATE_KEY

# Leave these blank for now — filled in after deploy
RAGG_TOKEN_ADDRESS=
GAME_REWARDS_ADDRESS=
```

> **Security:** Use two different wallets. The deployer wallet only needs tBNB
> once. The signer wallet key must stay on your server — never put it in
> the Unity project or commit it to git.

### 3c. Deploy to BSC Testnet

```bash
# Still inside RagglerChallenge/Blockchain/
npm run deploy:testnet
```

Expected output:
```
Deploying with: 0xYourDeployerAddress
Balance: 0.5 BNB

Deploying RaggToken...
RaggToken deployed at: 0xABC123...

Game signer address: 0xDEF456...

Deploying GameRewards...
GameRewards deployed at: 0x789GHI...

Setting GameRewards as minter...
Minter set.

✅ Deployment complete!
   RaggToken  : 0xABC123...
   GameRewards: 0x789GHI...
   Config written to Assets/Resources/ContractConfig.json
```

The script automatically writes `Assets/Resources/ContractConfig.json`.
Copy the two contract addresses into your `signer-server/.env`:

```env
RAGG_TOKEN_ADDRESS=0xABC123...
GAME_REWARDS_ADDRESS=0x789GHI...
```

### 3d. Verify contracts on BscScan (optional but recommended)

Get a free API key at https://testnet.bscscan.com/myapikey, add it to `.env`:

```env
BSCSCAN_API_KEY=YOUR_KEY_HERE
```

Then re-run the deploy script — it will verify automatically if the key is present.
Or visit https://testnet.bscscan.com and use the "Verify & Publish" button manually.

## 4. Moralis — Account & API Key

1. Go to https://admin.moralis.com and create a free account.
2. After login, click **Web3 APIs** in the left sidebar.
3. Copy your **API Key** (starts with `eyJ...`).
4. Add it to `signer-server/.env`:

```env
MORALIS_API_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

5. Also fill in the other required fields:

```env
JWT_SECRET=PASTE_A_RANDOM_64_CHAR_HEX_STRING_HERE
AUTH_DOMAIN=localhost          # or your real domain in production
AUTH_URI=http://localhost:3001 # or your real URL in production
```

Generate a safe JWT secret:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 5. Signer Server — Setup & Run

### 5a. Install dependencies

```bash
cd RagglerChallenge/Blockchain/signer-server
npm install
```

### 5b. Start the server

```bash
npm start
```

Expected output:
```
[Moralis] SDK initialised
[WS] WebSocket server initialised on /ws
Server listening on :3001
  Signer : 0xDEF456...
  WS     : ws://localhost:3001/ws
```

### 5c. Verify it's running

```bash
curl http://localhost:3001/health
```

Expected response:
```json
{ "status": "ok", "signer": "0xDEF456...", "moralis": true }
```

### 5d. Production deployment

For a live game, deploy the server to a host that supports:
- **Node.js 18+**
- **WebSockets** (persistent connections)

Recommended platforms: [Railway](https://railway.app), [Render](https://render.com), [DigitalOcean App Platform](https://www.digitalocean.com/products/app-platform)

After deploying, update `signer-server/.env`:

```env
BACKEND_URL=https://your-server.example.com
WS_URL=wss://your-server.example.com/ws
WEBHOOK_URL=https://your-server.example.com/streams/webhook
ALLOWED_ORIGIN=https://your-unity-game-domain.com
```

Then re-run `npm run deploy:testnet` so the deploy script writes the new URLs
into `Assets/Resources/ContractConfig.json`, or edit that JSON file manually:

```json
{
  "backendUrl": "https://your-server.example.com",
  "wsUrl": "wss://your-server.example.com/ws"
}
```

## 6. Moralis Streams — Register Contract Watcher

This is a **one-time setup** that tells Moralis to watch your GameRewards
contract and send webhook events to your server in real time.

> The signer server must be publicly reachable before running this step.
> If you're developing locally, use [ngrok](https://ngrok.com) to expose port 3001:
> ```bash
> ngrok http 3001
> # copy the https URL, e.g. https://abc123.ngrok.io
> ```
> Then set: `WEBHOOK_URL=https://abc123.ngrok.io/streams/webhook`

Run the setup script from `Blockchain/`:

```bash
# Make sure MORALIS_API_KEY, GAME_REWARDS_ADDRESS, and WEBHOOK_URL are set in signer-server/.env
node scripts/setupMoralisStream.js
```

Expected output:
```
Creating Moralis Stream...
  Contract: 0x789GHI...
  Webhook : https://your-server.example.com/streams/webhook
Stream created! ID: abc-def-123
Contract address attached to stream.

Add MORALIS_STREAM_ID to your .env:
MORALIS_STREAM_ID=abc-def-123
```

Copy `MORALIS_STREAM_ID` into your `signer-server/.env`.

To confirm it's working, complete a stage in the game later — your server logs
should show `[Streams] Event: StageRewardClaimed` within seconds of the tx confirming.

## 9. Unity — Card Prefab

### 9a. Create a Sorting Layer

1. Edit → **Project Settings → Tags and Layers**
2. Under **Sorting Layers**, click **+** and add: `Cards`, `CardUI`

### 9b. Build the prefab

1. In the **Hierarchy**, right-click → **Create Empty** → rename to `Card`
2. With `Card` selected, in the **Inspector** click **Add Component**:

| Component | Settings |
|---|---|
| `SpriteRenderer` | Sorting Layer: `Cards`, Order in Layer: `0` |
| `BoxCollider2D` | Size: `(0.9, 0.9)`, Is Trigger: off |
| `Card` (script) | leave all fields blank for now |

3. Drag `Card` from Hierarchy into `Assets/Prefabs/` to create the prefab
4. Delete the `Card` object from the Hierarchy (the prefab is saved)

### 9c. Prepare card sprites

Add 8–12 PNG images to `Assets/Sprites/`. For each sprite:

1. Select it in the Project panel
2. In Inspector set:
   - **Texture Type**: Sprite (2D and UI)
   - **Pivot**: Center
   - **Pixels Per Unit**: 100
   - **Filter Mode**: Bilinear
   - **Compression**: None
3. Click **Apply**

Suggested monster names (draw or use free pixel art):
`Poring, Lunatic, Fabre, Drops, Poporing, Smokie, Yoyo, ThiefBugEgg,
 Pupa, Spore, Willow, Chonchon`

3. Add all of these scripts as components:

| Script | Notes |

## 11. Unity — UI Canvas

### 11a. Create the Canvas

1. Hierarchy → right-click → **UI → Canvas**
2. **Render Mode**: Screen Space - Overlay
3. Add a **Canvas Scaler** component:
   - **UI Scale Mode**: Scale With Screen Size
   - **Reference Resolution**: `1280 × 720`
   - **Match**: `0.5`

### 11b. Add a UIManager object

1. Hierarchy → right-click → **Create Empty** → rename to `UIManager`
2. Add component: `UIManager`

### 11c. In-game HUD (create as children of Canvas)

Create these UI elements and drag them into the matching **UIManager** fields:

**Timer**
- UI → TextMeshPro - Text → rename `TimerText`
- Position: top-center, e.g. `(0, 330, 0)`, size `200 × 60`
- Font size: `36`, Alignment: Center
- → drag into `UIManager.timerText`

**Stars (3 images)**
- UI → Image × 3 → rename `Star1`, `Star2`, `Star3`
- Position them side by side below the timer
- Assign filled-star sprite to each
- → drag all 3 into `UIManager.starImages[]` (size 3)
- Assign your star sprites to `UIManager.starFilled` and `UIManager.starEmpty`

**Slot Count**
- UI → TextMeshPro - Text → rename `SlotCountText`
- Position: bottom-center above clearing zone, e.g. `(0, -270, 0)`
- → drag into `UIManager.slotCountText`

**Stage Label**
- UI → TextMeshPro - Text → rename `StageLabel`, top-left
- → drag into `UIManager.stageLabel`

### 11d. Power-Up Panel (right side)

Create a **Panel** named `PowerUpPanel`, position on right edge `(550, 0, 0)`.
Inside it, create 3 vertical groups — one per power-up:

**For each power-up (Remove / Undo / Refresh):**

```
PowerUpPanel
  ├── RemoveGroup
  │     ├── ChargesText      (TextMeshPro — shows "37")
  │     ├── RemoveButton     (Button)
  │     └── UsedText         (TextMeshPro — shows "0/10")
  ├── UndoGroup
  │     └── ... (same structure)
  └── RefreshGroup
        └── ... (same structure)
```

Wire buttons:
- **RemoveButton → OnClick** → drag `GameManager` object → select `PowerUpManager.UseRemove`
- **UndoButton → OnClick** → `PowerUpManager.UseUndo`
- **RefreshButton → OnClick** → `PowerUpManager.UseRefresh`

Wire text fields to **UIManager**:
- `removeCountText`, `undoCountText`, `refreshCountText` → the Charges texts
- `removeUsedText`, `undoUsedText`, `refreshUsedText` → the Used texts
- `removeButton`, `undoButton`, `refreshButton` → the buttons

### 11e. Stage Select Panel

1. Create a **Panel** named `StageSelectPanel`, full screen
2. Inside it, create a **Grid Layout Group** with 10 buttons (one per stage)
3. Add an **Endless** button at the end

Wire buttons:
- **Stage 1 button → OnClick** → `GameManager.StartStage` → set int to `0`
- **Stage 2 → int `1`**, ..., **Stage 10 → int `9`**
- **Endless button → OnClick** → `GameManager.StartEndless`

Wire to **UIManager**:
- `stageSelectPanel` → this Panel
- `stageButtons[]` → all 10 stage buttons (size 10)

### 11f. Result Panel

1. Create a **Panel** named `ResultPanel`, centered, initially inactive
2. Children:
   - `ResultStarText` (TextMeshPro) → `UIManager.resultStarText`
   - `NextButton` → OnClick → `GameManager.NextStage`
   - `RetryButton` → OnClick → `GameManager.RetryStage`
   - `MenuButton` → OnClick → `GameManager.GoToStageSelect`

- `resultPanel` → drag into `UIManager.resultPanel`

### 11g. Game Over Panel

1. Create a **Panel** named `GameOverPanel`, centered, initially inactive
2. Children:
   - TextMeshPro: "Game Over!"
   - `RetryButton` → OnClick → `GameManager.RetryStage`
   - `MenuButton` → OnClick → `GameManager.GoToStageSelect`

- `gameOverPanel` → drag into `UIManager.gameOverPanel`

## 14. Unity — WebGL HTML Template

After building, open `WebGL-Build/index.html` and add this line in the `<head>`
**before** the Unity loader script. This loads ethers.js which the jslib bridges require:

```html
<head>
  <!-- ADD THIS LINE -->
  <script src="https://cdn.jsdelivr.net/npm/ethers@6/dist/ethers.umd.min.js"></script>

  <!-- existing Unity scripts below -->
  <script src="Build/raggler.loader.js"></script>
  ...
</head>
```

If you want a custom WebGL template (so you don't have to edit after every build):

1. Copy `Assets/WebGLTemplates/Default/` to `Assets/WebGLTemplates/RagglerTemplate/`
2. Open `index.html` inside it and add the ethers.js `<script>` tag
3. In Player Settings → WebGL Template → select **RagglerTemplate**

## 17. Troubleshooting

**"MetaMask not found"**
→ Install the MetaMask browser extension. The game only runs in a browser
with MetaMask (Chrome, Brave, Firefox).

**"Please switch to BSC Testnet"**
→ MetaMask auto-prompts to add the network. Accept it. If it fails, add manually:
- Network Name: `BSC Testnet`
- RPC URL: `https://data-seed-prebsc-1-s1.binance.org:8545/`
- Chain ID: `97`
- Symbol: `tBNB`
- Explorer: `https://testnet.bscscan.com`

**"Could not reach game server"**
→ Check your signer server is running and `RewardManager.backendSignerUrl`
in Unity matches its address exactly (including `https://` for production).

**"Invalid signature" from the contract**
→ The `GAME_SIGNER_PRIVATE_KEY` in `.env` must match the `gameSigner` address
stored in the deployed `GameRewards` contract. If you changed the key after
deploying, call `setGameSigner()` on the contract (owner only) with the new address.

**"No improvement: stars not higher than best"**
→ This is expected behaviour — the contract correctly blocks double-claiming.
The game should not show a MetaMask popup for this case; if it does, check
the `RewardManager.OnStageComplete` delta check (`stars > chainBest`).

**Balance not updating after claim**
→ Check server logs for `[Streams] Event: StageRewardClaimed`. If missing,
the Moralis Stream may not be configured — re-run `setupMoralisStream.js`.

**Unity console errors about DllImport**
→ These only work in a WebGL build — the editor stubs log to Console instead.
This is normal. If you see errors in a WebGL build, check the `.jslib` files
are in `Assets/Plugins/WebGL/` and the function names match exactly.

**Cards not blocking each other correctly**
→ The overlap threshold in `BoardGenerator.AssignCoveringRelationships()` is
`0.6f` units. If your card sprites are scaled differently, adjust this value
to match roughly half the card width.
